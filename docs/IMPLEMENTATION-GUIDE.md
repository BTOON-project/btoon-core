# Implementing BTOON

How to build a conforming BTOON implementation, plus the API conventions every BTOON
library follows so they feel like one family. The byte-level contract is
[SPEC.md](SPEC.md). This guide covers what the spec leaves to implementers.

## 1. Conformance checklist

An implementation conforms to spec 0.1 when its test suite runs
[`tests/vectors/btoon-vectors.json`](../tests/vectors/btoon-vectors.json) as follows:

- every non-error vector decodes to its `value`;
- every `"canonical": true` vector re-encodes from `value` to exactly its `hex`;
- every error vector is rejected, with the error `code` equal to the vector's `error`;
- vectors with `"options"` are run with those options. Vectors with `"requires"` may be
  skipped when the codec isn't available.

Vendor a copy of the vectors file into your repo and keep it in sync with core. Never
edit the copy by hand. The vectors are regenerated by `tests/vectors/generate.py`.

## 2. Encoder notes

**Integers.** Pick the format from the value, never from the source type. In languages
with one integer type (Python, PHP, JS numbers) this is natural. In typed languages
(C++, Go) a `uint64(5)` and an `int8(5)` both encode as `05`.

**Floats.** Always emit float64. Canonicalize NaN to `7ff8000000000000`. Go's
`math.NaN()` is `7ff8000000000001`, so Go must canonicalize explicitly. Keep `-0.0`.
JS: a `number` that is a safe integer (`Number.isSafeInteger`) and not `-0` encodes as an
integer. Other numbers, including `-0` and integral values outside the safe range,
encode as float64.

**Map key order.** Sort keys by their UTF-8 **bytes**. This differs from UTF-16 code-unit
order (JS `sort()`, Java) for characters outside the BMP. Compare encoded byte arrays,
or code points, which give the same order for UTF-8.

**Tabular.** Apply the qualification test and the size rule of SPEC §5.6.2 *exactly*.
This is what makes canonical output identical everywhere:

```
qualifies(rows):  len(rows) ≥ 2, every row is a map, first map non-empty,
                  every row has exactly the first row's key set
use_tabular:      N*(maphdr(C) + Σ(strhdr(len k) + len k)) > 18 + Σ(9 + len k)
                  (len k = UTF-8 byte length; maphdr/strhdr = MessagePack header sizes)
```

Write the payload, then patch in the length. Because the ext header comes first and
its size depends on the payload length, encode into a temporary buffer, or reserve 6
bytes and shift the payload down afterwards. `type_code` comes from the logical type of
the first row's value (SPEC §5.6.1). The simplest exact way is to read it off the first
byte of that cell's encoding, after encoding it. C++ core does this, and an ext whose
type is -10 counts as an array. In dynamic languages, check booleans before integers if
you derive the code from the value instead.

The C++ `Encoder` exposes the same steps to bindings that encode directly from their
own objects:
`beginTabular(names, rows)` → for each column `beginTabularColumn()`, write the N cells,
`endTabularColumn()` → `endTabular()`. Use `tabular_beneficial(rows, key_lengths)` for
the size rule, and `apply_envelopes()` to compress or sign the result.

**Timestamps.** Use the MessagePack selection algorithm (SPEC §5.1). Emit the 14-byte
offset form only when the caller explicitly asks to keep an offset. Normalize ordinary
datetimes to UTC.

**Depth.** Count containers exactly as SPEC §7 does, and fail with `max_depth` (default
128). This is how cyclic object graphs become errors instead of stack overflows.

## 3. Decoder notes

- Read through a bounds-checked cursor; never index past the end.
- Before reserving an array or map, check `count ≤ remaining` (or `2*count` for maps).
- Recurse with an explicit depth counter.
- Validate UTF-8 for strings, keys and column names in strict mode. JS:
  `new TextDecoder('utf-8', {fatal: true})`. Python: `bytes.decode('utf-8')`. Go:
  `utf8.Valid`. PHP: `mb_check_encoding($s, 'UTF-8')` or `preg_match('//u', $s)`.
- Reject duplicate keys in strict mode, including duplicate tabular column names.
- Decode a tabular column with a sub-reader limited to `col_len` bytes. It must hold
  exactly N values. Check `N × C ≤ remaining payload` before allocating rows.
- Envelopes: check the header fields and the `uncompressed_size` limit *before*
  decompressing. Stop decompressing at the declared size: a stream that wants to
  produce more is invalid, and so are bytes left after the end of the stream. Bound
  the Zstd window as SPEC §6 describes.
- A bigint extension whose value fits in 64 bits is the same logical integer as the
  plain encoding (SPEC §7). Dynamic languages decode it to their native integer. Typed
  languages may return their big-integer type, but must compare it by value.
- Report errors with the SPEC §7 codes. Tests compare them.

## 4. API conventions

Every library exposes the same small surface, adapted to the language's idioms:

| Concept | Python | JS / TS (`btoon`, `@btoon/js`) | Go | PHP |
|---|---|---|---|---|
| encode | `btoon.encode(v, **opts) -> bytes` | `encode(v, opts?) -> Uint8Array` | `btoon.Marshal(v) ([]byte, error)`, `MarshalWithOptions` | `BTOON\encode($v, $opts = [])` |
| decode | `btoon.decode(b, **opts)` | `decode(bytes, opts?)` | `btoon.Unmarshal(b, &v)`, `btoon.Decode(b) (any, error)` | `BTOON\decode($s, $opts = [])` |
| error | `btoon.BtoonError` (`.code`) | `BtoonError` (`.code`) | `*btoon.Error` (`.Code`) | `BTOON\BtoonException` (`->errorCode`, `getErrorCode()`; `->error` is the `ErrorCode` enum) |
| generic ext | `btoon.ExtType(code, data)` | `new Ext(type, data)` | `btoon.Ext{Type, Data}` | `new BTOON\Ext($type, $data)` |
| timestamp w/ ns | `btoon.Timestamp` | `Timestamp` | `time.Time` (native ns) | `BTOON\Timestamp` |

Option names (snake_case in Python/PHP arrays, camelCase in JS, fields in Go):

| Encode option | Default | Meaning |
|---|---|---|
| `compress` | false | Wrap in a compression envelope (zlib unless `compression` names another). |
| `compression` | `"zlib"` | `"zlib" \| "lz4" \| "zstd" \| "brotli" \| "snappy"`. Unavailable ones raise `unsupported_compression`. |
| `auto_tabular` | true | Use the columnar encoding when the size rule says so. |
| `max_depth` | 128 | Nesting limit; deeper (or cyclic) input raises `max_depth`. |
| `hmac_key` | none | Sign the output (SPEC §8). |

| Decode option | Default | Meaning |
|---|---|---|
| `strict` | true | SPEC §7 strict mode. |
| `max_depth` | 128 | Nesting limit. |
| `max_decompressed_size` | 256 MiB | Envelope size limit. |
| `auto_decompress` | true | Accept compression envelopes. |
| `hmac_key` | none | Require and verify a signed envelope. |

## 5. Type mappings

Decoding produces the language's idiomatic types by default. Precision-preserving
wrapper types are available where the idiomatic type loses information.

| BTOON | Python | JS / TS | Go (`Decode` into `any`) | PHP |
|---|---|---|---|---|
| nil | `None` | `null` (`undefined` encodes as nil) | `nil` | `null` |
| bool | `bool` | `boolean` | `bool` | `bool` |
| integer | `int` | `number` if safe integer, else `bigint` | `int64`, or `uint64` above MaxInt64 | `int`; above `PHP_INT_MAX` → `BTOON\BigInt` |
| bigint (-4) | `int` | `bigint` (`number` when safe, with `bigint: 'auto'`) | `*big.Int` | `BTOON\BigInt` (decimal string; GMP if present); `int` when it fits |
| float | `float` | `number` | `float64` | `float` |
| string | `str` | `string` | `string` | `string` |
| binary | `bytes` (accepts `bytearray`, `memoryview`) | `Uint8Array` (Node binding: `Buffer`) | `[]byte` | `string`, or `BTOON\Binary` with `binary_as_object` |
| array | `list` (accepts `tuple`) | `Array` | `[]any` | list `array` |
| map | `dict` | plain object (accepts `Map` with string keys) | `map[string]any` | associative `array` |
| timestamp (-1) | aware `datetime` (UTC; offset → `timezone`) | `Date` (ms); `Timestamp` with `timestamps: 'object'` | `time.Time`; `btoon.Timestamp` with `PreserveTimeTypes` | `DateTimeImmutable`; `BTOON\Timestamp` with `timestamps => 'object'` |
| date (-2) | aware `datetime` | `Date` | `time.Time`; `btoon.Date` with `PreserveTimeTypes` | `DateTimeImmutable`; `BTOON\Date` with `timestamps => 'object'` |
| datetime (-3) | aware `datetime` | `Date` | `time.Time`; `btoon.DateTime` with `PreserveTimeTypes` | `DateTimeImmutable`; `BTOON\DateTime` with `timestamps => 'object'` |
| float32 vector (-5) | `array('f')` (numpy with option) | `Float32Array` | `[]float32` | `BTOON\VectorF32` |
| float64 vector (-6) | `array('d')` | `Float64Array` | `[]float64` via `btoon.VectorF64` | `BTOON\VectorF64` |
| other ext | `btoon.ExtType` | `Ext` | `btoon.Ext` | `BTOON\Ext` |

Encoding accepts the same types in reverse, plus common extras:
- Python `tuple`, `bytearray`, `memoryview`, `datetime` (naive is treated as UTC), and
  `array.array('f'/'d')`.
- JS `Map`, `Date`, `ArrayBuffer`/DataView/other typed arrays (as binary), and `bigint`.
- Go structs (via `btoon:"name,omitempty"` tags, falling back to `json` tags),
  `time.Time`, `*big.Int`, `[]float32` (as a float32 vector), `encoding.BinaryMarshaler`,
  pointers and interfaces.
- PHP `JsonSerializable` objects, `stdClass`, `DateTimeInterface`, and `GMP`.

An instant that the native type can't hold (a JS `Date` covers ±8.64e15 ms, a Go
`time.Time` ends near year 292 billion) decodes to the library's timestamp type instead
of failing or wrapping around.

Ambiguities are resolved the same way everywhere:
- An empty PHP array encodes as an empty **array**. Pass an `ArrayObject` or `stdClass`
  for an empty map.
- A JS `number` that is a whole number, such as `2.0`, encodes as an integer. There's no
  way to tell it apart from `2` in JS.
- A PHP string that is not valid UTF-8 encodes as **binary** (strict decoders reject
  invalid UTF-8 in `str`). Wrap a value in `BTOON\Binary` to force binary.

### Pitfalls found while porting

- **PHP zlib:** `gzuncompress($data, $max)` can return more than `$max` bytes and ignores
  trailing garbage. Use `inflate_init()` and `inflate_add()` on bounded input slices,
  then check `inflate_get_status()` and `inflate_get_read_len()`.
- **PHP zstd:** ext-zstd's `zstd_uncompress()` pre-allocates the frame's declared size,
  has no output limit, and ignores truncation and trailing bytes. Validate the frame
  header yourself and decompress incrementally (ext-zstd 0.15 or later).
- **PHP LZ4 and Brotli:** ext-lz4 before 0.8 only writes size-prefixed blocks, so use
  the 0.8 `lz4_*_raw()` functions. ext-brotli can't bound its output or detect trailing
  bytes, so the PHP library reports Brotli as unsupported.
- **PHP exceptions:** `Exception::$code` is a protected int, so the spec's string code
  lives in `$e->errorCode`.
- **JS streams:** Node 20's `DecompressionStream` ignores bytes after the end of a zlib
  stream. Check the Adler-32 trailer, or use an inflater that reports unused input.
- **JS strings:** a lone surrogate has no UTF-8 form. Both npm packages raise
  `invalid_utf8`. Node-API's `napi_get_value_string_utf8` and `TextEncoder` silently
  write U+FFFD instead, so check before converting.

## 6. Packaging conventions

- Version every library as `0.1.x` while it targets spec 0.1. Put the spec version in
  the README and expose it as a constant (`SPEC_VERSION`).
- Compression: zlib is mandatory. Other codecs are optional, and missing ones raise
  `unsupported_compression` rather than silently writing uncompressed output.
- Every repo's CI runs its unit tests plus the vectors on each push and pull request.
